playwrightDemo - One-page repo summary

Evidence-based summary from repo files (README.md, playwright.config.ts, tests/, .github/workflows/playwright.yml).

What it is

Small Playwright Test (TypeScript) demo repository that runs end-to-end browser automation against public demo sites and outputs an HTML report.

Application source code under test: Not found in repo (tests target external websites).

Who it's for

Developers and QA/SDET engineers learning or prototyping Playwright Test patterns in TypeScript.

How to run

npm ci npx playwright install npx playwright test npx playwright show-report

Notes: Requires internet access (tests navigate to external sites). Optional config: npx playwright test -c playwright.config.dev.ts

What it does

  • Runs Playwright Test specs in tests/ using @playwright/test.
  • Executes across Chromium, Firefox, and WebKit with HTML reporting and trace capture on first retry.
  • Validates login flows (Opencart account login + the-internet login) and negative login error messaging.
  • Demonstrates interactions: form fill, role-based locators, dropdown select, focus, checkbox/radio checks, and locator chaining.
  • Includes smoke coverage for the "Challenging DOM" page, with retry/skip on intermittent server errors.
  • Demonstrates HTTP Basic Auth via an Authorization header.
  • Shows a persistent browser context with a profile stored under test-results/.

How it works (architecture)

  • Runner: npx playwright test loads playwright.config.ts (browser projects + HTML reporter).
  • Tests: Specs drive page interactions and assertions against external URLs (e.g., the-internet.herokuapp.com, naveenautomationlabs.com).
  • Resilience: Helper tests/helpers/opencart.ts retries navigation and skips when unreachable.
  • Outputs: HTML report in playwright-report/; run artifacts in test-results/.
  • CI: GitHub Actions workflow installs deps + browsers, runs tests, and uploads the HTML report artifact.

Not found in repo

  • A local app/server to start via Playwright webServer (config block exists but is commented out).
  • Centralized test data/secret management (some tests use hard-coded credentials and values).
